Hi! This folder explains the whole database project assuming you know
almost nothing about how databases work inside. No jargon without
explanation. Read the files in order - each one builds on the last.

THE BIG PICTURE IN ONE PARAGRAPH

A database is a program that stores information so that:

  1. it survives restarts and crashes (durability),
  2. you can find any piece of it very fast even among millions of rows,
  3. many questions ("queries") can be asked safely at the same time.

LeafDB does all three. It stores data in fixed-size blocks called
PAGES, organizes them with a tree structure called a B+ TREE for fast
lookup, writes every change to a journal called the WRITE-AHEAD LOG
before touching the data file so crashes can't corrupt anything, and
understands enough SQL to run real queries with joins and grouping.

A NOTE ON FEAR

None of this requires math beyond counting. The ideas are simple:
sorted lists, pointers between pages, and writing things down before
you act. If an explanation below ever feels heavy, take a break and
re-read the analogy at its start - the analogies carry the truth.
